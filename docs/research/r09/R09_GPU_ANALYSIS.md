Root viewport timestamp відображає GPU-роботу viewport і може відставати від кадру. GPU% і VRAM — телеметрія пристрою, яка включає compositor. CPU головного потоку — /proc/PID/task/PID/stat. Render setup — engine counter. Показники не складаються з GDScript scopes в один незалежний бюджет.

Pause зупиняє fixture tick loop із тією самою камерою, зберігаючи GUI й візуальні _process. NetHash на початку й кінці pause збігся, у pause було нуль simulation ticks. Headless виконував відповідний workload у burst. Його tick wall time характеризує вартість симуляції за відсутності GPU-рендерингу. GUI FPS й headless loop rate мають різні значення.

Збільшення роздільної здатності, зменшення zoom і переміщення камери контролюють різні складники рендерингу. При активних прогонах зберігаються NetHash і стрім команд. Висновок ґрунтується на pause/headless і main-thread utilization разом із GPU timestamps. Шейдери окремо, bandwidth і зовнішній present trace — NOT RUN.

## Висновок контрольних прогонів

D2100 обмежений головним потоком у протестованій конфігурації. Активний GUI тримає приблизно 99% одного потоку, GPU viewport займає 1,56 мс при медіані кадру 44,75 мс. Pause з тією самою камерою дає 61,97 FPS проти 20,11. Headless медіана тика 20,88 мс близька до GUI 22,10 мс. Ці контролі підтверджують значну складову власне симуляції.

Розмір 960×540, 1280×720 і 1853×1011 дав 20,46, 20,11 і 19,68 FPS при GPU p50 0,65, 1,56 і 2,99 мс. Додаткова GPU робота від пікселів має слабкий ефект на загальний кадр у цьому режимі. Зсув камери з приблизно 609 до 0 юнітів у viewport дає 27,02 FPS за близької вартості тика і збігу стану симуляції. Видима область впливає на загальну вартість і через роботу CPU підготовки. Ширший zoom у D2100 дав 18,25 FPS за того самого медіанного лічильника наземних юнітів. Зміна zoom також змінює деталі й набір графічних об’єктів, тому окремого коефіцієнта на видимого юніта тут немає.

Viewport API повертав нуль для render object count у цих 2D прогонах, тому поле позначено як недоступне. Draw calls, viewport-ground і map sprite counts походять з різних лічильників. Перші два наведено вище, кількість map sprites є в long-run таблиці та workload samples. Показники пам’яті і температури — у raw host.csv. У першому D2100 основному прогоні медіани близько 1991 MiB RSS, 555 MiB VRAM, 75 °C CPU і 48 °C GPU. Для висновку про memory bandwidth потрібні апаратні лічильники.
