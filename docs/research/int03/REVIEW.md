# INT-03 · Review PR #11

> Історичний матеріал з `toolchain/int03.IGMm9Fth/REVIEW.md`. [Реєстр досліджень](../INDEX.md)

База beta `11380ee014cae95c1bdc2367b0ee9a1b8cbfed7b`, розглянутий PERF-03 `41c586bfa3df6e80b0faf54f621d4c82ba5beae4`.

- `_range_tel` використовує ті самі умови `TEL`, власник, `alive`, нерухомість і відсутність консервації. Установки без боєзапасу залишаються придатними для пояснення. Чинний фільтр пулу розподілу незалежний і збережений.
- Перевірка відстані лишає обидві межі включними за тими самими `Vector2.distance_to` і порівняннями `> MISSILE_RANGE` та `< MISSILE_MIN`. Короткий пошук дає ту саму відповідь, що й перевірка порожнечі відсортованого списку.
- Запас, порядок цілей, вибір при рівності та резервування лишаються в попередньому циклі. Пояснення продовжують розрізняти дипломатичну заборону, дальність, дефіцит, перезарядку і відсутність ОТРК.
- `center_px` обчислюється з клітинки й розміру установки. Список позицій збирається при першій відмові в межах одного синхронного виклику. Планувальник не очікує на події й виконує `strike_block_at(..., false)` без записів повідомлень. Наступний виклик будує свіжий список. Сортування для інших споживачів `tels_for` збережено.
- Змішані й відкладені пуски повторно планують актуальний запас, як раніше. Поза планувальником PERF-03 змінює тільки тести та звітність. У bump змінено тільки метадані версії, локалізовану примітку «Що нового» та version assertions.
- У попередньому PERF-03 500/420 дало 88,89 → 16,31 мс, 500/250 — 244,71 → 13,14 мс, 500/0 — 493,77 → 8,19 мс. За повного боєзапасу GUI INCONCLUSIVE, медіана headless CPU 12,92 → 12,92 мс. Ці дані отримано на Linux Vulkan і RTX 4060 Laptop GPU. Повну матрицю в INT-03 не повторювали.
- Політика admission використовує точний рядок версії, тому peers 0.36.1 і 0.36.2 відхиляються як різноверсійні, включно зі старим MP resume. Формат звичайних збережень, PROTO, SIM_REV, NetHash і код admission збережені.
- Єдиний активний GitHub workflow запускає перевірки для PR і push у beta. Публікація в ньому вимкнена через `release=false`, кроків створення тегів чи deployment немає. Classic protection для beta відсутній, effective ruleset порожній, merge commits дозволені. Обидві автоматичні перевірки вимагаються власником перед merge.
