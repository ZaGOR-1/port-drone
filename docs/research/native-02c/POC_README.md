# NATIVE-02C · Native Vision Mask Processing

> Історичний матеріал з `toolchain/native-02c/NATIVE-02C-handoff.tar.gz::handoff/source/research/native-02c/README.md`. [Реєстр досліджень](../INDEX.md)

**NO_GO на етапі профілювання.** Верхня межа економії всієї пакетної обробки масок становить **0,86 мс/тик** у D5000 і **1,31 мс/тик** у щільному D5000. Додатковий щільний замір кожного stamp дав **1,25 мс/тик**. Це межа за нульової вартості обчислення та передачі даних. Rust PoC і A/B після цього gate не потрібні.

База `93bd6afdfb51b4dfb5c6d04e3339e37bbdbda035`, версія 0.36.9. Official Godot 4.7.2 `ed1daf0bf`, готовий Linux runtime INT-10, Profile B harness і CPU clock із NATIVE-02B. Профіль працював на фізичних копіях чистої beta, з активною видимістю, у звичайній desktop-сесії Ubuntu. Vulkan Forward Mobile на RTX 4060 Laptop, 1280×720, без VSync і FPS cap. На прогін 45 warm-up і 90 залікових тіків. Медіани стороннього CPU 11,17–11,35%. Семплер не спостерігав VM або компілятор у залікових вікнах.

## Поточна вартість

CPU головного потоку, мс за 90 тіків. Вкладені фази наведено для атрибуції.

У D5000 було 28 перебудов, 27 798 спроб stamp, 11 388 ground blits і 588 air blits. У щільному D5000 відповідно 41, 40 758, 16 712 і 861. Повна ціна stamp у цих двох прогонах оцінена за кожним 16-м викликом. Підтверджувальний щільний прогін заміряв усі 38 722 stamp за 39 перебудов. Stamp, прямокутники міст, очищення масок і dedup та публікація байтів коштували 112,15 мс, або 1,25 мс/тик. Це 21,89% заміряного `Vision.update` та 1,96% від CPU окремої lockstep-симуляції. Часті таймери додали витрати в області збору джерел, тому її оцінку взято з легшого профілю.

Обидві маски мають 256×256 пікселів L8, разом 128 KiB на публікацію. Сумарний логічний обсяг пар за 90 тіків 3,50 і 5,13 MiB відповідно. `Image.get_data()` повертає Godot `Vector<uint8_t>`, який ділить буфер через copy-on-write. Зміна `Image` може відокремити буфер, поки маска має посилання на старий. Ціна можливого відокремлення входить у `fill`. Обсяг публікацій описує розмір масок, а фактичні копії рушія окремо не лічилися. `Image.fill`, `fill_rect`, `blit_rect_mask` і `get_data` вже виконуються в C++. Піксельний цикл blit у Godot читає альфу шаблону RGBA8 і копіює L8, після обрізання прямокутників.

У залікових вікнах не було `Image.create`, створення stamp-шаблонів або текстури. Перед заліковим вікном щільна діагностика зафіксувала 0,010 мс для однієї алокації пари Image, 0,071 мс для трьох шаблонів і 0,096 мс для однієї текстури. Окремих викликів `Image.convert` у цьому шляху немає. Vulkan renderer відображає L8 у R8_UNORM зі swizzle, валідує Image та передає дані через RenderingDevice. Таблиця показує CPU виклику текстури на головному потоці. GPU upload окремо не вимірювався.

## Межа і довідкова продуктивність

Можлива вузька межа проходить після обходу живих City/Facility/Unit, інших джерел і правил дружності. Пакет міг би записати готові ground/air байти, включно з обрізанням і перекриттям, та повернути їх для queries і ground texture. Основний щільний прогін дає 117,97 мс за 90 тіків для всієї цієї роботи. Навіть якщо додати до потенційної економії весь CPU виклику texture update, межа лишається 1,32 мс/тик. Перебирання джерел та оцінка споруд необхідні після такого перенесення. 30% повного `Vision.update`, орієнтир 2 мс/тик і 5% simulation CPU для цього обсягу роботи поза виміряною межею.

## Семантика і перевірки

Ground-mask живить shader fog і `sees()`. У SP цю перевірку використовують, зокрема, правила артилерійських наказів, перевірка ворогів для будівництва та AutoCmd. `sees_air()` читає об'єднання ground, air і дружньої території. Air-внесок у перевірених викликах використовується для локального показу, звуку, вибору видимих об'єктів та попереджень, зокрема `Recon.RDrone.warned`. У MP `Vision.update` і текстура працюють поза `net_step`. Маски відсутні в `NetHash` і є транзієнтними в `Vision.save_state`. Перевірені gameplay-обмеження видимості в AutoCmd, Operations і Military вимкнені для `net_driven`. Локальні попередження й fog UI продовжують читати маски.

У всіх трьох профілях кінцеві NetHash, RNG і серіалізовані команди збіглися з історичними контрольними даними. Це перевірка цілісності профілювання. Побайтова еквівалентність з Rust, differential fixtures, чотири окремі deterministic replays, GUI A/B та фізичний Windows QA — NOT RUN після відсіву на етапі профілювання. Дерево `game/` в гілці ідентичне beta. Відомі повідомлення Godot про teardown ресурсів лишаються в сирих логах.

Handoff з raw files, інструментацією, відтворенням, точними SHA256 PCK/runtime та звітом знаходиться в `/home/zagor/projects/droneflames-toolchain/native-02c/handoff/`.
