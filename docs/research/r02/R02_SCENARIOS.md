# R02 · Сценарії й відтворення

> Історичний матеріал з `toolchain/performance/R02_SCENARIOS.md`. [Реєстр досліджень](../INDEX.md)

Використано наявний performance worktree і R01 runner. `--r02` відкриває локальний patched Windows package. Звичайні сценарії R01 залишаються доступними. Seed карти 20261016, глобальний seed 91234, карта 1024×1024. Основні GUI прогони uncapped з вимкненим VSync, 1280×720, 150 ticks прогріву. Реальні розміри збережено в raw JSON.

| Tier | Початковий fixture | Завершена вибірка |
| --- | --- | --- |
| A | 216 наземних, 144 записи споруд, 1 фронт | 450 ticks |
| B | 600, 360, 3 фронти | 1 800 ticks |
| C | 1 200, 720, 3 фронти | 2 × 1 800 ticks |
| D | 1 920 або 2 100, 1 080, 3 фронти | 2 × 1 800 для 1 920, 1 800 для 2 100 |
| E | Старт C, поповнення і втрата військ шляхом реальних ticks | 4 500 ticks після прогріву, 155,86 с wall, snapshot |

Ramp 200/400/600/800/1000/1200/1500/1800 тримав 720 початкових записів споруд і однакову кількість резервних казарм. Розгортання округлює кількість юнітів униз до кратної шести. Потік команд і тривалість однакові. У межах кожної вибірки війська, живі споруди, ефекти і снаряди природно змінюються. C-light має один фронт, C-no-ai має шість сценарних командних потоків, C-540 має 960×540. C-light і C-no-ai виявились у вікні 1853×1011, тому їх не використовували для строгого A/B з C-main.

Команда для наступної сесії, якщо повтор санкціоновано:

```bash
cd /home/zagor/projects/droneflames-toolchain/performance
python3 run_r01.py --r02 D r02-runs/local-d2100 \
  --units 2100 --warm-ticks 45 --ticks 1800 --timeout 200
```

Для реального checkpoint використати копію звичайного FORMAT 1 SP save через раніше перевірений R01 entrypoint `python3 run_r01.py D runs/user-late --save /path/to/copy.save --adaptive --warm 180 --frames 1200 --timeout 180`. Новий імпорт SP save і відновлення R02 E snapshot наявні в діагностичних скриптах, але **NOT RUN**. Формат локального network snapshot E відрізняється від користувацького SP save. `r02-runs/e-long/state.snapshot` збережений для окремої перевірки restore.

Runner має окремий Wine prefix, process RSS ceiling 3 100 000 KiB, host MemAvailable floor 1 550 000 KiB, timeout та внутрішній вихід після 8 секунд поспіль із кадрами понад 200 мс. Вибірки завершувалися за заданою кількістю тиків. Два діагностичні EXE збережені окремо у `package-r02` та `package-r02-lan`. `build_r02.sh` використовував готовий Godot template. Поточний diff worktree (`R02_DIAGNOSTICS.patch`) містить також локальні hooks LAN і restore, яких немає в EXE основної серії.
