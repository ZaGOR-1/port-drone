# R13 · Методика раннього gate

> Історичний матеріал з `toolchain/performance/r13.C0NIjw0t/evidence/METHOD.md`. [Реєстр досліджень](../INDEX.md)

База `8c83d91d06989cc3857c7560c4690188bf88a964`, версія `0.36.5`. Копія performance/portable отримала профіль r13 і матеріалізувала точне джерело в окремому каталозі. Обидва кандидати використовують той самий official Linux 4.7.2 runtime з INT-06/DEV-02. PCK для fixtures готуються у фізичних копіях. Пакети користувача лежать за межами раннього gate.

## Етап A

Перша серія D2100 і C1200 використовує два різні probes. `phases-A` підраховує фактичні гілки руху та distinct Unit IDs, таймери гарячих фаз використовує на кожному шістнадцятому виклику. Рідкі операції замірюються суцільно. Ці оцінки включають вартість знімання часу й використовуються для вибору операції. `profile-A` окремо вимірює `Army.update`, `_advance` і їхні вкладені функції. Inclusive тут включає nested probes. Exclusive віднімає заміряні дочірні виклики й накладні витрати цих викликів за правилами спільного профайлера. Скопи є wall time головного потоку, їх не складають із батьківськими.

Прямі lookup прохідності `_dry_step` використовують biome array. Для рідкісних fallback `ground_at` читає bridge flags і bridge_cells. `_blocked` та `_reroute` можуть звертатися до навігації. Перевірка 3×3 fort cells працює умовно. У звичайному `_advance` немає обходу сусідніх юнітів або physics collision query. Швидкість, waypoint, state/cover і rotation входять до наявного циклу. Розподілу нативних heap allocations у цій серії немає.

## Етап B

`path_blocked(u)` у базі викликається на кожному `_advance`, після його false гілка ще раз читає `blocked_path` і перевіряє порожнечу. Більшість викликів йде по порожньому маркеру. У PoC `_advance` один раз перевіряє порожній маркер, для непорожнього зберігає exact PackedVector2Array equality, retry deadline, `_reroute` і очищення застарілого маркера в тому самому порядку. Метод `path_blocked` лишається для своїх інших callers. `has_waypoint` обчислюється після можливого reroute і спільно використовується для переходу з FIGHT і маршруту. Поля Unit звичайні, setter у переході стану немає. Формули швидкості, відстані, прохідності й запису позиції ідентичні. Історичний R04 перевикористовував next position. Його патч лишився окремою гіпотезою.

## Етап C

17 рухових assertions і byte-identical differential JSON, потім 90 fixed-clock тіків D2100 та C1200 з порівнянням стану. Мінімальні GUI пари використовують 45 warmup та 120 measured ticks, однаковий seed 20261016, camera position, 1280×720, zoom 1.111111, VSync/cap off. Рендерер і GPU перевіряються у кожному run log. CPU scopes знімаються окремими профільними парами. Порядок A/B, B/A, A/B для D2100, A/B і B/A для C1200. Підготовка тестових PCK завершена до вимірювань. Записано process snapshots, температуру та відліки завантаження під час кожного прогона.

Перший локальний runner зупинився після baseline differential, бо відкритий Bash-процес зчитав попередню цільову кількість assertions до виправлення harness. Результат A містив 17 перевірок без помилок. Gate перезапущено з належною перевіркою 17 в обох варіантах. Релевантні benchmark дані знято після цього.
