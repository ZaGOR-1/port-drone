# R06 · Локальний PoC

> Історичний матеріал з `toolchain/performance/r06/R06_CHANGES.md`. [Реєстр досліджень](../INDEX.md)

Єдина зміна симуляції в B — розрахунок швидкості для RailTroops.plan у гілці _check, де наземний маршрут ще PENDING і немає waypoint. Виклик _speed(f) будував новий масив через глобальний _army(f). Патч бере той самий мінімум Army.SPEC[u.type]["speed"] з уже зібраного mem для u.post == null.

order_units(f) починається з _army(f), зберігаючи порядок живих наземних юнітів потрібної казарми без поста, reinf і виключень _kept. Для країни гравця order_units дописує лише юнітів із post != null. Фільтр у новій гілці залишає той самий впорядкований підмасив. Від збору mem до розрахунку підказки sync-навігація читає склад армії й оновлює лише маршрутний стан. Послідовність minf і fallback 8,0 збережені.

У кожному E replay прибрано 450 повних обходів глобального списку зі шляху черги. Усі викликачі Operations._army разом показали 480 усунених обходів і 487 307 відвідувань елементів. Кількість відкладених результатів, викликів order_units, маршрутних запитів у черзі та legal_route збіглася. Додатковий тимчасовий масив від _army більше не створюється у цій гілці.

Локальний список живе лише до завершення _check. Порядок черги, виклики планувальників, момент застосування, RNG, Save Format і Multiplayer Protocol збережені. A і B мають однакову діагностику. Фізичні staging-дерева game відрізняються одним файлом, operations.gd. PoC diff (`R06_OPTIMIZED.patch`) · Порівняння staging (`stage-game-diff.txt`) · SHA256 (`R06_SHA256SUMS.txt`)
