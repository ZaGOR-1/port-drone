# NATIVE-02 · ArmyFire.ImpactUnits.candidates()

> Історичний матеріал з `toolchain/native-02/NATIVE-02-handoff.tar.gz::handoff/source/research/native-02/README.md`. [Реєстр досліджень](../INDEX.md)

Дослідницький PoC зі збирання й сортування рангів. База 0.36.9, `93bd6afdfb51b4dfb5c6d04e3339e37bbdbda035`. Toolchain і параметри gdext успадковано з NATIVE-01 `b19c66c80e1d93e7546f3f2d3ed79fd7470bd9cc`.

**Дослідницький GO.** У щільному D5000 цільова CPU-фаза скоротилася на 66,39% за медіаною пар. Абсолютний виграш близько 0,94 мс/тик у щільному і 0,10 мс/тик у звичайному D5000. Рекомендація для production — відкласти інтеграцію. Для окремої функції виграш замалий, щоб виправдати підтримку ще однієї нативної бібліотеки, ABI, двох backend і перевірки пакування на Windows.

## Контракт

- GDScript будує індекс R18 та визначає межі й порядок обходу клітинок. GDScript перетворює відібраний bucket на `PackedInt32Array` при першому використанні в поточному поколінні індексу. Всі копії packed buckets очищаються в `invalidate()` або разом зі звільненням `ImpactUnits` наприкінці batch.
- Один виклик `NativeImpactRanks.gather` на індексований impact передає `Array[PackedInt32Array]`. gdext отримує packed handles, Rust позичає їхні slices і копіює ранги в один вихідний `PackedInt32Array`. Ядро сортує цілі ранги на місці. Однакові значення залишаються в результаті. Повторення одного `Unit` у registry зберігається як окремі ранги.
- На межі виклику є лише ранги та packed handles. Native-об'єкт не зберігає handles, slices чи стан симуляції між викликами. GDScript читає `Unit` за поточним registry, перевіряє відстань, застосовує ефекти й відновлює обхід суфікса при вкладеному виклику. За відсутності класу працює початковий GDScript-збір і сортування. Якщо R18 повертає `null`, виконується чинний повний обхід.
- У базовому `game/` клас опційний. Для експерименту його реєструє окремий manifest у фізичній копії гри. Reload вимкнено. Release використовує `panic = "abort"`, тому помилка всередині native бібліотеки може завершити процес.

## Локальна збірка

Використати готові Rust/Cargo 1.100.0 та Windows GNU target з NATIVE-01 і офіційні Godot 4.7.2 runtime з INT-10. З каталогу `research/native-02`, з `CARGO_HOME`, `RUSTUP_HOME` і `PATH` NATIVE-01 та окремим `CARGO_TARGET_DIR`:

```sh
cargo fmt --check
cargo test --offline --locked --release
cargo build --offline --locked --release
cargo build --offline --locked --release --target x86_64-pc-windows-gnu
```

Для копії `game/` додати manifest `native02.gdextension` в `native-02/` і рядок `res://native-02/native02.gdextension` в `.godot/extension_list.cfg`. Запакувати копію штатним `tools/packproj` із фізичної копії інструмента. Поруч з runtime/PCK покласти `native-02/libnative02.so` або `native-02/native02.dll` відповідно до платформи. Скрипт `prepare.py` у handoff відтворює тестові Linux PCK з R18B harness. Варіант A збирається з заданого коміту beta, B з цієї гілки, варіант fallback з цієї гілки без manifest.

## Real-World Gaming

A зібрано з чистої beta 0.36.9. B використовує той самий official Linux x64 runtime й ті самі R18B replay fixtures у Vulkan Forward Mobile на RTX 4060 Laptop. Роздільність 1280×720, VSync і FPS cap вимкнено. Для кожного сценарію виконано один screening і три пари по 45 тіків warm-up та 90 залікових, із чергуванням A/B. Таймер R18 міряє час CPU головного потоку. FPS і frame/tick p99 використовують elapsed time. Фонові застосунки працювали в звичайному режимі. У залікових плечах медіани стороннього CPU по плечах були 10,55–14,20% доступних CPU. Серед найбільших споживачів були VS Code, Discord, Chrome і Steam. Семплер не зафіксував VM чи компілятора у вікнах шести основних пар.

Фаза рангів — інструментована `candidates()` разом із підготовкою batch, алокацією та звільненням lookup і повернутих рангів. Із її часу віднято спільну для A/B побудову й очищення індексу R18, вартість очищення packed кешу повернуто. Повний життєвий цикл у таблиці включає спільні витрати. Найгірші парні зміни FPS та 1% low у щільному D5000 були +0,63% і −4,45%; медіани +0,77% і −2,00%. Peak RSS змінився за парними медіанами на +1,04% у D5000 і −0,48% у щільному D5000.

У щільному B 866 запитів повернули 981 457 рангів (~3,74 MiB чистих i32 за 90 тіків). Медіани B дали 13,93 мс на відбір разом з 4,43 мс на пакування і 12,84 мс на повний виклик Rust з отриманням результату GDScript. Початкова перевірка та створення адаптера в межах batch разом з наступними перевірками готовності зайняли 1,80 мс. Інвалідація packed кешу зайняла 0,12 мс, очищення lookup при завершенні batch 3,11 мс, звільнення результатів 0,79 мс. Обхід результатів після повернення, включно з геометрією та ефектами, заміряно окремо в `rank_visit`. Абсолютна медіанна економія цільової фази у щільному D5000 становить 84,30 мс за 90 тіків, приблизно 0,94 мс/тик і 1,38% CPU базової симуляції.

Додаткове інструментоване GUI-плече B на тому самому щільному сценарії розклало 14,97 мс round-trip на читання packed handles 1,26 мс, алокацію/resize виходу 2,04 мс, копіювання рангів 1,13 мс, Rust sort 7,53 мс і звільнення handles 0,60 мс. Залишок 2,41 мс включає маршалінг, FFI й накладні витрати таймерів. Залишок обчислено різницею таймерів. Перетворено 1 960 buckets з 198 195 рангами, а запити використали 11 328 входжень packed buckets. Та сама діагностика дала 144,55 мс на першу побудову і 5,67 мс на перебудови. Висновок gate використовує звичайну збірку та її три пари.

Короткі контролі після підтвердження виграшу. У D2100 цільова фаза 17,48 → 16,31 мс, FPS 20,20 → 20,40, 1% low 8,93 → 9,27. У Late E одна пара дала FPS 36,23 → 30,27 (−16,46%) і 1% low 9,43 → 8,13 (−13,81%). У цьому вікні обидва плеча мали нуль індексованих запитів, а сторонній CPU зріс з 11,05% до 13,93%. Причинність GUI-розбіжності Late E **INCONCLUSIVE**.

## Детермінізм і QA

- Rust 3/3, build identity 3/3. NATIVE-02 differential 56/56 з .so backend на Linux і 37/37 без розширення. R18 core і city/rail 46/46 та 7/7 у кожному з A, B та fallback. Покрито порожні buckets, повтори рангів і посилань, заміну registry однакового розміру, invalidation/rebuild, spawn/kill, реальну rail-висадку, вкладені `_impact` і `_update_shells`, а також чинний R17 membership lookup.
- У 420 покрокових зіставленнях D5000, dense D5000, D2100 і Late E збіглися NetHash, RNG, authoritative unit state, шляхи, стан Operations/watchdog, послідовність impact effects і command traces. Збіглися серіалізовані пакети команд, кінцеві контрольні хеші R18B та побайтні фінальні snapshots. Late E пройшов дві повторні restore у кожному плечі й мав нуль native-запитів. Ідентичність 0.36.9, PROTO 7, SIM_REV `v036-integration-1`, Save.FORMAT 1, 30 тіків/с.
- Official Linux GUI та Win64 Rust cross-build PASS. Official Windows x64 release template під Wine пройшов headless smoke D2100 із 286 native-запитами у 60 залікових тіках. Фізичний Windows GUI/FPS, LAN/Steam і повна регресійна матриця мають статус NOT RUN. Логи містять відомі teardown warnings про ресурси Godot.
