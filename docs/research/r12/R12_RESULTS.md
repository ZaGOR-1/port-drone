## Причина та зміна

Кожна команда `_spr` двічі читає метадані за іменем, створює source rectangle з `x + w * frame`, `y`, `w`, `h` та відновлює anchor з `ax, ay`. Потрібні ті самі значення для багатьох юнітів з одним варіантом і кадром. PoC перевикористовує пару `Rect2` і `Vector2` для основного атласу, окремо для тіней і тіл, за ключами name та frame. Обидва словники живуть у межах одного виклику. Destination залежить від позиції кожного юніта і обчислюється як раніше. Legacy atlas, texture lookups, culling, fog, animation, buckets, draw order та overlays збережено.

При zoom 1,111 D2100 відвідав 1877,62 юніта за кадр, пройшли culling 671,72. Збережено 671,72 body, 671,72 shadow і 1372,43 sprite submissions у ground scope разом з іншими спрайтами. За 60 кадрових samples усунено по 73 644 повторні source rectangles та anchors, або **1227,40 кожного за кадр**. Геометричні metadata lookups знизилися з 2744,87 до 290,07 за кадр. Texture lookups і destination rectangles збіглися. PoC створює в середньому 116,03 масива geometry entries, 18 вкладених і два зовнішні словники за кадр. Реальні heap allocations не вимірювали. Кількість видимих у цьому положенні камери майже не змінилася між zoom 0,833, 1,111 і 1,667. Щільний контроль підняв середню кількість юнітів у камері до 1942,33.

## Результати

RTX 4060 Laptop GPU, Ubuntu native, official Godot 4.7.2, Vulkan Forward Mobile, 1280×720, VSync і cap off. Мінімальна FPS матриця та детальні CPU вимірювання окремі. Однакові початкові й кінцеві хеші, камера, команди та стан для кожної пари. Чистий повтор замінив C1200 пару 3 і Medium пару 1, чиї A-вікна перетнулися з підготовкою локальних PCK. У трьох детальних парах D2100 inclusive `_ground_units` **3,424 → 3,244 мс/кадр**. Shadow pass 0,802 → 0,670, body pass 0,615 → 0,509. Exclusive залишок поза чотирма вкладеними фазами 0,812 → 0,868. Сукупний UnitsLayer 7,244 → 7,300 мс/кадр. У C1200 inclusive 2,098 → 1,766, у щільному D2100 10,588 → 8,343, у паузі 8,100 → 6,168 мс/кадр. У детальному paused control було по два виклики ground на sample, симуляція й NetHash заморожені. Його FPS описує тільки контроль рендера.

D2100 FPS за парами 20,876 → 20,975, 20,835 → 20,719, 21,144 → 18,277 і 20,833 → 20,479. У гіршій парі приріст часу кадру 7,418 мс, з яких 4,449 припали на виміряний tick. Медіана host CPU зросла 23,45 → 31,45%, але причинність не встановлено. У четвертій парі кадр +0,831 мс, tick +0,958 мс. Підвищення витрат у профілі _ground_units для цих випадків не підтверджене окремими детальними вимірюваннями. C1200 дав кращі загальні метрики, а чистий повтор дав лише 41,205 → 41,378 FPS. Результати не визначають, яку частину загального розкиду спричинив PoC.

## Коректність і пакування

Visual assertions 43/43 на варіант. Вісім screenshot-пар попіксельно однакові, ordered draw traces збігаються. Перевірено zoom, resize, viewport edge, selection, типи, фракції, рухові кадри, legacy atlas, fog, night tint, щільне перекриття та повторне створення шару. Реальний GameWorld lifecycle 8/8 на варіант. У коректному повторі обидва варіанти мали 448 ObjectDB instances і 45 resources still in use при виході. Історичні Godot warnings лишаються відкритими.

Python 49/49 без SKIP, simulation 2476, watchdog 101, ring 8, HUD/input 36, R10 differential 49×2 із однаковими trace, L10N, ENet admission/reconnect/resync, Linux native та Wine headless smoke пройшли. Windows official x64 і Linux QA build мають той самий PCK. Фізичний Windows GUI/A/B, LAN і Steam — NOT RUN.

C1200, D2100 та Late E збіглися на 150/150 тіках. Late E підтвердив NetHash 4693 `f19767f333c29101`, 4746 `c9301a1dcbcd76e8`, 4800 `3c338abc3ec9d5c7` та RNG `1940658711`. Активний D2100 Save/Load зі спільного й власного save збігся на 66/66 тіках. PROTO 7, SIM_REV v036-integration-1, Save.FORMAT 1, tick rate 30, NetHash, wire і перевірка повної версії збережені.

**Наступний підтверджений sustained scope — `Army._advance`.** У цьому D2100 він мав 4,885 мс/кадр inclusive на A, близько 1437 викликів/кадр. R11 окремо виміряв 4,27–4,50 мс/кадр exclusive нижче p99. Рух лишається авторитетним, тому наступна робота потребує scoped characterization для шляхів і waypoint arrival. Реалізацію не починали.
