# FIX-01 — походження дефектів

Джерело звіту — нативний запуск Windows x64 на ПК друга користувача. Пакет `DroneFlames-PR7-Windows-x64-0e8316e.zip`, гра 0.36.0, Godot 4.7.2, source `0e8316ee167b11a90925e33a126290b6848d9986`, SHA256 `883668885c8f75e882b17b9330bbaac0e34c16e240c14da3e5f739eb1e3674c1`. Роздільну здатність, DPI й параметри миші цього ПК не зафіксовано.

| Дефект | Причина | Відтворення |
|---|---|---|
| BUG-01 | Підказка групи задавала мінімальну ширину майже в увесь viewport. Початок панелі зміщувався до центру відносно вужчої цільової ширини. Високі popover мали окреме обмеження лише координат. | Вихід редактора й високого popover за межі на beta і SHA пакета PR #7. |
| BUG-02 | Коліщатко після обробки GUI могло спливти з Control. Обробник карти пропускав modal check для wheel. | Той самий playback давав zoom над Settings і scrim на обох базах. |
| BUG-03 | Миша використовувала сенсорні `_dtz` і `_dtz_drag`. Два натискання протягом 320 мс і в межах 50 одиниць запускали zoom з якорем курсора або strategic dive. Зсув якоря змінював позицію камери. | Серії ЛКМ без руху та з мікрорухами змінювали стан камери на обох базах. Окремо виправлено очищення жесту після поглинутого GUI release. |

Однакові твердження регресійного fixture виконано на `c91e0e6` та `0e8316e`. Критичні ділянки placement і вводу збігаються. Переклад здатен змінити ширину підпису, проте причини відтворено незалежно від PR #7. База `fix/hud-camera-input` — `beta` `c91e0e6`.

Падіння продуктивності після вибору понад приблизно 200 цілей ОТРК передано до PERF-01. Звіт користувача і SHA пакета опубліковано в [QA-коментарі PR #7](https://github.com/ZaGOR-1/port-drone/pull/7#issuecomment-7116888734).
