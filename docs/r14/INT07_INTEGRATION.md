## Цільовий review

`Army._hostile` відхиляє однаковий ID, отримує країну за індексом і перевіряє наявність ключа в `at_war`. R14 залишає явну перевірку того самого ID і ту саму належність ключа, включно зі значенням `false`. Відсутня країна дає порожній словник. Нейтральні, дружні та спеціальні ID проходять той самий предикат.

Посилання на країну й словник беруться після шкоди наземним і морським цілям та після сигналів видалення укріплень. До першого `_damage` обхід виконує лише читання полів, `is_line`, `center_px` і `alive`, включно з гілками для депо та АЕС. Ці операції не викликають мутацій або сигналів. Після `_damage` одразу виконується `break`. Навіть синхронна зміна дипломатії при руйнуванні не може вплинути на вибір наступної споруди в цьому циклі. Наступна міська фаза звертається до чинного `_hostile`. Порядок реєстру, включна межа квадрата відстані, формула шкоди, RNG, події, статистика й наземна фаза R10 збережені.

## Performance і приймання

У D2100 обхід споруд 3,583 → 2,011 мс/кадр, inclusive `_impact` 7,275 → 5,188 мс/кадр. FPS покращився в усіх чотирьох парах, медіана 19,996 → 20,647. CPU симуляції 25,831 → 24,478 мс/тик, 1% low 7,042 → 7,224, frame p99 138,455 → 128,632 мс. Щільний D2100 дав +4,88% FPS і −7,49% CPU симуляції. У C1200 frame p95 зріс на 6,37%, у двох щільних парах зріс tick p99, медіана +3,11%. В одній парі D2100 знизився 1% low, пік RSS зріс на 0,65% за медіанами D2100. Причинність цих відхилень лишається відкритою. Щільний синтетичний контроль R10 окремо зафіксував додаткову вартість влучання, коли наземний guard не відсікав жодного юніта. [Заміри R14](R14_RESULTS.md) · [Ризики R10](../r10/INT06_INTEGRATION.md#продуктивність-і-p99)

Фізичні Windows GUI/FPS, LAN і Steam — NOT RUN для R14. Власник відклав ці перевірки для інтеграції. DummyTexture, mesh is null та історичні teardown warnings лишаються відкритими. Наступна перевірка кандидата — фізичний Windows A/B.
