# Development Workflow

Зафіксована база для цієї роботи — beta c91e0e6. Локальна beta відстежує origin/beta, origin/main — стабільний ref. У доступній історії тегів немає. Наявні короткі Conventional Commits та merge commits від accepted PR. Вкладених AGENTS.md на базі немає. CI будує Windows x64 і ганяє Python/Godot fixtures. Вбудований release job блокує публікацію навіть за ручного запиту.

1. Звір актуальну базу, статус і релевантні worktrees. Для нового завдання створи тематичну гілку й worktree. Продовжуй логічний набір змін у чинній гілці.
2. Сформуй невелику зміну й запусти релевантні тести. Godot запускай з фізичної копії або готового PCK в ізольованому профілі.
3. Звір status, staged diff і секрети. Додавай файли явно. Після перевірок зроби локальний Conventional Commit, наприклад `fix(l10n): resolve mixed-language UI strings`.
4. Зафіксуй у `PROJECT_STATE.md` перевірені SHA, незавершений QA, версію та гілку. Для погодженого push перевір `origin`, worktree, історію, секрети, бінарні артефакти й віддалений ref. Публікуй лише погоджену робочу гілку.
5. Перевір наявний PR за його head і base. Для інтеграції в `beta` створи Draft PR, якщо потрібен додатковий QA. Додай фактичні результати, коміти та ризики, тоді звір віддалений HEAD і статус PR. Дозвіл на merge, переписування опублікованої історії чи реліз узгоджуй окремо за правилами `AGENTS.md`.
