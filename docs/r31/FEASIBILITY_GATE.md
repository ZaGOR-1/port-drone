## Дешевий screen

Один rendered replay на fixture D2100 restore (4800 + 120 тіків), Late E (4650 + 150) і C1200 (45 warm-up + 60). Діагностика в фізичній копії, зі штатним результатом пошуку для симуляції. Для B=8/16/32 ізольовано виконати packed-маски на реальних даних з кожного виклику. Звести за tick, окремо показати D2100 4816/4864, Late E 4682/4746 і контроль. Виміряти CPU головного потоку для скалярного пошуку, побудови блоків, перевірки актуальності й запиту, рахувати cold/invalidated/reused і нульові сегменти відносно відвіданих. Повний неселективний скан масок можна виконувати для oracle поза CPU кандидата. Shadow — діагностика потенціалу. Подвійний запуск пошуку, counters і спільний cache/topology можуть вплинути на CPU. Для оцінки чистого watchdog CPU віднімати від scalar `_wd_tick` тільки виміряну замінену роботу й додавати повну роботу кандидата. Замість оптимістичного віднімання нового часу від історичних CPU брати скаляр того ж replay. Плату COW між викликами встановити окремо або вказати нижню межу витрат і область невиміряних витрат.

Прохід до PoC лише за точного збігу результату всіх sampled searches, консервативного предиката і життєздатної інвалідації. Для основного тика 4816 потрібен потенціал ≥5 мс і ≥10% `_wd_tick` після всіх виміряних витрат, з перевіркою, що невраховані витрати не закривають запас. Якщо швидкий безпечний шлях потребує широких змін writers або навіть оптимістична ціна не дає порогового виграшу, verdict NO-GO для перевіреного дизайну. Непридатні докази через середовище або порушення еквівалентності без атрибуції дають INCONCLUSIVE. Розмір для PoC — найкращий за чистим CPU на 4816 серед тих, що проходять, з перевіркою напряму на 4746.

## Умовне приймання PoC

До A/B: exact scalar differential і ordered trace на межах блоків і карти, парність радіусів 47/48, strict tie, neutral weighting, no-exit, різні land components, owners/biome replacements та edits, diplomacy passage/station, callback між викликами, lifecycle new world, repeated restore. Replay має зберегти команди, RNG, NetHash, paths і watchdog state. Потрібні same-seed, FORMAT1 Save/Continue, repeated/negative snapshot restore і host/peer до вимірювань.

По **4 послідовні пари на кожен** з D2100 restore, Late E й C1200, порядок AB, BA, AB, BA. Це 24 плеча. Кожне плече має завершити зазначене вище вікно на однакових scenario settings, seed 20261016, режимі Vulkan Mobile, 1280×720, zoom 100, тому самому runtime й потокові команд. Зберегти всі спроби. Невалідні пари зафіксувати і повторити в тому самому порядку, коли є технічна причина, модель агрегації та пороги фіксовані. Для кожної метрики спершу рахувати абсолютну й відносну парну різницю, далі медіану і min/max чотирьох різниць. Показати окремо 4816, 4864, 4746. На 4816 потрібні обидва пороги **≥5 мс та ≥10%** CPU `_wd_tick` за медіаною пар, включно з інвалідацією й доданою роботою поза `_wd_tick` у відповідному вікні. На 4746 потрібна додатна чиста економія. Для кожного сценарію guard **5%** у несприятливому напрямку за медіаною пар для tick p99, frame p95/p99, FPS, 1% low, peak RSS і peak VRAM. Фіксувати p50/p95/p99/max, main-thread runnable wait, фоновий CPU і memory pressure. Якщо відмінність середовища заважає атрибуції, verdict INCONCLUSIVE. Фізичний Windows QA після локального GO.
