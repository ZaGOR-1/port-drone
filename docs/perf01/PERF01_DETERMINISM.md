# PERF-01. Детермінізм

Два UI-покращення працюють до формування наказу. Список цілей, його порядок, правила перевірки і розподілу ракет, тік симуляції, RNG, `NetHash` та формат Save зберігають чинні реалізації. Готовий боєзапас обчислюється штатним `missiles_ready` із тими самими умовами, які визначають поле `available` повного плану.

GUI A/B перевіряє однакові тексти призначення та підписи кнопки на всіх контрольних кількостях, порядок виділення та повернення чернетки після закриття, перемикання вкладок зброї, панорамування, зум і роботу UI в uk, ru та en. Вибір до 500 цілей і дії HUD залишили NetHash `c8749401923c35cd`. Після 105 фіксованих кроків SP обидва варіанти отримали `a72f51f055913276` і 250 активних ракет першої хвилі.

Режим `--verify-mp` відправляє подію кнопки у фактичний `NetSession.call_sim` з локальним хостом. Fixture перевіряє один наказ після подвійного підтвердження, порядок цілей у фактичному wire payload і відхилення наказу без чинного відправника. Позитивний наказ проходить штатний `NetSession._exec` та `GameWorld.cmd_strike`. Далі виконується 105 кроків `net_step` з `SIM_DT = 1/30`. Перевірка черг потрібна окремо від NetHash, бо відразу після формування черги він у цьому сценарії збігається з початковим.

| Цілей | Ракет у черзі A=B | Активних після 105 кроків A=B | NetHash після 105 кроків A=B |
| ---: | ---: | ---: | --- |
| 50 | 50 | 50 | `92efa3ce28fb0a3c` |
| 200 | 200 | 200 | `b158bde3c0bb723f` |
| 300 | 300 | 250 | `e1ac3fe366391da7` |
| 500 | 500 | 250 | `e1ac3fe366391da7` |

SHA256 фактичних команд і черг збіглися для всіх чотирьох кількостей. Повні значення збережено в `performance/perf01/determinism.json`.

Фізичний MP з двома клієнтами — **NOT RUN**. Версія в гілці кандидата `0.36.1`; `PROTO=7`, `SIM_REV=v036-integration-1` і `Save.FORMAT=1`. Повна ідентичність мережевого лобі після PATCH має вигляд `v0.36.1/7/v036-integration-1`. Штатна перевірка рівності версії вимагає однакової збірки на обох клієнтах і для resume мережевого матчу. Окремо пройшли simulation regression 2476/2476 і Python discovery 43/43, включно з Save/Load, повторним restore, admission та updater identity. Штатні headless fixtures пройшли Windows UI 20/20, keyboard 130/130 і UI scale 26/26. Для scale використано фізичну копію проєкту зі штатним `override.cfg` і наявними Linux debug libraries, щоб завантажити PcPort.
